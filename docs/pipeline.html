Prednisone equivalency

convert_pred_equiv( drug_df, drug_col = "drug_name_std", dose_col = "daily_dose_mg_imputed", equiv_table = NULL, drug_name_map = NULL )

Multiplies each record's daily dose by the appropriate prednisone-equivalency factor:

DrugFactorNotes
Prednisone1.0Reference drug
Prednisolone1.0Equipotent
Methylprednisolone1.251 mg methylpred = 1.25 mg pred
Triamcinolone1.25
Dexamethasone7.5High potency
Hydrocortisone0.25Low potency
BudesonideNARoute-dependent; flagged for manual review

Pass a custom equivalency table via equiv_table to override or extend the built-in table. The table must have columns drug_name_std and equiv_factor.

Episode building

build_episodes( drug_df, id_col = "person_id", drug_col = "drug_name_std", start_col = "drug_exposure_start_date", end_col = "drug_exposure_end_date", dose_col = "daily_dose_mg_imputed", gap_days = 30L, concurrent_agg = c("per_drug", "sum_all") )

Merges overlapping or adjacent prescription records within a patient–drug group into continuous treatment episodes using OHDSI-standard gap-era logic (equivalent to DrugUtilisation 30-day era). The concurrent_agg parameter controls how prescriptions of different steroids that overlap in time are handled (see below).

Key parameters

ParameterDefaultDescription
gap_days30LMaximum gap in days between consecutive records still merged into the same episode (OHDSI standard).
extra_cols v0.4.0character(0)Optional character vector of column names to carry from the input records into the episode summary by statistical mode (most common value per episode). Example: extra_cols = "parsed_status" propagates NLP parse status so that evaluate_against_gold()$stratified$by_sig_status is automatically populated for error decomposition.
concurrent_agg v0.2.0"per_drug" How to handle concurrent prescriptions of different steroids:
"per_drug" — each drug tracked independently (one episode track per patient–drug pair).
"sum_all" — day-expand all records, sum doses across all drugs per patient-day, then gap-bridge the daily totals. Returns one drug_name_std = "total_steroids" track per patient. Use with dose_col = "pred_equiv_mg" for cross-drug summation to be meaningful.

Concurrent dose handling

By default (concurrent_agg = "per_drug"), each drug is tracked independently — concurrent prescriptions of different steroids appear as separate episode rows. This is the standard OHDSI approach.

When concurrent_agg = "sum_all", the algorithm:

  1. Day-expands every prescription record to one row per calendar day covered.
  2. Sums all drug doses for the same patient on the same day (cross-drug total).
  3. Gap-bridges the resulting daily-total series using the same 30-day era rule.
  4. Returns one episode per patient with drug_name_std = "total_steroids" and dose statistics reflecting the combined daily burden.

Important: set dose_col = "pred_equiv_mg" before calling build_episodes() when using concurrent_agg = "sum_all". Summing native drug doses across different steroids (e.g., prednisone 5 mg + methylprednisolone 4 mg) is not comparable; prednisone-equivalent units put all drugs on a common scale. If a different dose_col is supplied and multiple drugs are present, a warning is emitted.

In CodeToRun.R, set the top-level config variable CONCURRENT_AGG <- "per_drug" (or "sum_all") and all three methods pick it up automatically.

Gap-bridging algorithm

  1. Sort each patient–drug group chronologically by start date.
  2. Maintain a running-maximum end date across processed records. This means overlapping records (gap < 0) are always merged into the same episode without special handling.
  3. Start a new episode only when the gap from the running-max end to the next record's start exceeds gap_days.
  4. Summarise the merged episode: episode_start = min(start), episode_end = max(end), and the dose statistics below.

Dose summary for an episode

All four statistics are computed across the individual records merged into the episode:

ColumnFormulaWhen to use
median_daily_doseMedian of record dosesDefault; robust to outlier records within an episode
mean_daily_doseΣ(dose_i × days_i) / Σ(days_i)Duration-weighted; longer prescriptions count more — recommended when episode contains dose changes
min_daily_doseMinimum across recordsConservative lower bound
max_daily_doseMaximum across recordsConservative upper bound

Pass computed_dose_col = "mean_daily_dose" to evaluate_against_gold() to use duration-weighted mean instead of median for the accuracy comparison.

Output columns (one row per episode)

Evaluation against a gold standard

evaluate_against_gold( computed_df, gold_df, min_overlap_days = 1L, computed_id_col = "person_id", computed_start_col = "episode_start", computed_end_col = "episode_end", computed_dose_col = "mean_daily_dose", gold_id_col = "person_id", gold_start_col = "episode_start", gold_end_col = "episode_end", gold_dose_col = "median_daily_dose", dose_breaks = c(0, 10, 20, 40, Inf), dose_labels = c("Low (<=10mg)", "Medium (10-20mg)", "High (20-40mg)", "Very High (>40mg)") )

What is a matched episode?

The comparison table has one row per gold-standard episode. A gold episode is matched when at least one computed episode for the same patient overlaps it by ≥ min_overlap_days calendar days (default: 1). When multiple computed episodes overlap the same gold episode, the one with the most overlap days is selected and its dose is used for the comparison. Unmatched gold episodes have computed_dose = NA and are counted as uncovered in coverage_pct.

The total gold episode count (n_gold_periods) and matched count (n_matched_periods) are always reported in $summary, regardless of which patients overlap between the computed and gold sets.

Key parameters

ParameterDefaultDescription
min_overlap_days1LMinimum calendar-day overlap required to match a computed episode to a gold episode.
computed_dose_col"mean_daily_dose" v0.4.0Dose column to compare against gold. Default changed to duration-weighted mean — more reliable than median for tapered episodes. Can also use "median_daily_dose", "min_daily_dose", or "max_daily_dose".
dose_breaks v0.1.6c(0, 10, 20, 40, Inf)Cut-points for dose-range stratification in $stratified. Default bins are tuned for typical myositis maintenance doses.
dose_labels v0.1.6c("Low (≤10mg)", …)Labels for the dose ranges. Change both parameters together to customise for other diseases.

Return value

A named list with three elements:

  • $summary — One-row summary: n_gold_periods, n_matched_periods, coverage_pct, MAE, MBE, RMSE, median_AE, MAPE, pearson_corr, spearman_corr
  • $comparison — One row per gold episode: gold_dose, computed_dose, overlap_days, absolute_error, bias_error, agreement_category, error_direction
  • $stratified — Metrics broken down by: by_dose_range (always), by_taper_status (when has_taper column present), by_sig_status v0.4.0 (when sig_status column present at episode level)

Agreement categories

Poor (>50%)> 50%

Prednisone-equivalent units throughout

Computed episodes: run_pipeline() calls convert_pred_equiv() before build_episodes(), so the median_daily_dose column in every episode output is already in mg prednisone-equivalent, not in native drug units. When episode trajectories display a drug name (e.g. methylprednisolone) alongside median_daily_dose, the dose is pred-equiv mg — not native methylprednisolone mg.

Gold standard standardization

The gold standard CSV stores median_daily_dose in the native drug unit as recorded by the chart reviewer. Before calling evaluate_against_gold() it must be converted to pred-equiv so both sides are on the same scale.

Because the gold standard does not carry a drug-name column, the drug identity is inferred by overlapping each gold episode with baseline_df (oral-filtered) and taking the most-frequent drug_name_std. Important: baseline_df is used instead of raw drug_df to exclude injection records — an injection that overlaps the gold window would produce a wrong conversion factor.

After joining the drug name, convert_pred_equiv() is applied. If the drug cannot be identified (no overlapping oral records, or drug not in the equivalency table), the raw dose is kept via coalesce(gold_pred_equiv_mg, median_daily_dose). These episodes carry pred_equiv_status != "ok" and are counted in the "drug unknown (kept raw)" line printed to the console — their dose errors may be systematically wrong and should be interpreted with caution. 

# identify the dominant drug for each gold episode
gold_drug_map <- drug_df |>
  left_join(gold_std |> select(patient_id, episode_start, episode_end),
            by = c("person_id" = "patient_id"), relationship = "many-to-many") |>
  filter(as.Date(drug_exposure_start_date) <= as.Date(episode_end),
         as.Date(drug_exposure_end_date)   >= as.Date(episode_start)) |>
  group_by(patient_id = person_id, episode_start, episode_end) |>
  count(drug_name_std, sort = TRUE) |>
  slice_max(n, n = 1L, with_ties = FALSE) |> ungroup()

gold_std <- gold_std |>
  left_join(gold_drug_map, by = c("patient_id", "episode_start", "episode_end")) |>
  convert_pred_equiv(drug_col = "drug_name_std", dose_col = "median_daily_dose",
                     out_col = "gold_pred_equiv_mg") |>
  mutate(median_daily_dose = coalesce(gold_pred_equiv_mg, median_daily_dose))

Example

gold_std    <- readr::read_csv(file.path(extdata, "synthetic_gold_standard.csv"),
                             show_col_types = FALSE)
eval_result <- evaluate_against_gold(episodes, gold_std)

s <- eval_result$summary
sprintf("Coverage: %.1f%%  MAE: %.2f  MBE: %.2f  RMSE: %.2f",
        s$coverage_pct, s$MAE, s$MBE, s$RMSE)

Error decomposition by parse category v0.4.0

After running evaluate_against_gold(), use stratify_errors_by_parse() to see whether errors concentrate in clinically interpretable SIG categories (taper, PRN, free-text, no_parse) versus well-parsed records — a table manuscript reviewers commonly request. 

# Build NLP episodes with parse status propagated
nlp_ep <- build_episodes(
  nlp_df,
  end_col    = "drug_exposure_end_date",
  dose_col   = "daily_dose_mg",
  extra_cols = "parsed_status"   # propagate by mode per episode
)
ev <- evaluate_against_gold(nlp_ep, gold_std,
                            gold_dose_col = "dose_daily_mg_equiv")

# Join parse status back onto the comparison table
comp <- ev$comparison |>
  dplyr::left_join(
    nlp_ep |> dplyr::select(person_id, episode_start, parsed_status),
    by = c("person_id", "episode_start")
  )

stratify_errors_by_parse(comp, "parsed_status")
# Returns: category | n | n_matched | coverage_pct | MAE | MBE | MAPE | median_AE

Preventing gold-standard leakage during threshold tuning: if you use tune_hierarchical_thresholds() to select match_tol and diff_threshold, always tune on a held-out patient subset and evaluate on the remainder. make_validation_split() does this split at the patient level (never by episode, so no patient appears in both folds): 

gold_split <- make_validation_split(gold_std_ok, train_frac = 0.7)
thresh_res  <- tune_hierarchical_thresholds(drug_df, gold_df = gold_split$train)
# Then evaluate best params on gold_split$validate — unbiased estimate

Binary detection evaluation v0.4.0

evaluate_against_gold() measures dose accuracy for patients already known to be on steroids. A complementary question is whether the pipeline correctly identifies who is on steroids at all — especially when you also have a cohort of patients confirmed to have never used steroids. evaluate_detection() answers this with a standard 2×2 confusion matrix and Cohen's kappa.

evaluate_detection( computed_df, gold_positive_df, gold_negative_df, detection_threshold = 0, obs_window_source = c("computed", "explicit", "study"), study_start = NULL, study_end = NULL, computed_id_col = "person_id", computed_start_col = "episode_start", computed_end_col = "episode_end", computed_dose_col = "median_daily_dose", gold_pos_id_col = "patient_id", gold_pos_start_col = "episode_start", gold_pos_end_col = "episode_end", gold_neg_id_col = "patient_id", gold_neg_start_col = "obs_start", gold_neg_end_col = "obs_end" )

Two-stage evaluation framework

Detection evaluation (Stage 1) and dose accuracy evaluation (Stage 2) answer different questions and should be run separately:

  • Stage 1 — did we detect steroid use? Use evaluate_detection() with confirmed users and confirmed non-users. Produces kappa, sensitivity, specificity.
  • Stage 2 — how accurate is the dose among detected users? Use evaluate_against_gold() on the TP subset (or the full gold positive cohort). Produces MAE, MAPE, agreement categories.

Classification logic

Computed dose ≥ thresholdComputed dose < threshold or absent
Gold positive (confirmed user)True Positive (TP)False Negative (FN)
Gold negative (confirmed non-user)False Positive (FP)True Negative (TN)

Gold positives are evaluated at the episode level — a gold episode is TP when a computed episode for the same patient overlaps it by ≥ 1 day and has computed_dose >= detection_threshold.

Gold negatives are evaluated at the patient level — because a confirmed non-user has no treatment episode, no date window can be defined from the gold data alone. Instead the observation window is derived from one of three sources (see obs_window_source below).

Key parameters

ParameterDefaultDescription
detection_threshold0Minimum computed dose (mg pred-equiv/day) to count as detected. Use 5 or 10 to exclude trace/artifact doses.
obs_window_source"computed"How to define the observation window for gold-negative patients. See table below.
study_start / study_endNULLRequired when obs_window_source = "study". Accepts Date or ISO character.
gold_neg_start_col / gold_neg_end_col"obs_start" / "obs_end"Required when obs_window_source = "explicit".

Observation window options for gold negatives

obs_window_sourceWindow definitionBest when
"computed" (default) Window = all computed episodes for that patient. Patients absent from computed_df are automatically TN. No explicit observation period is available; any detection in the data constitutes a false positive.
"explicit" Each row in gold_negative_df carries its own obs_start / obs_end (e.g. enrolment period). Each patient has a known follow-up window (e.g. from a registry or observation_period table).
"study" A single fixed date range (study_start to study_end) applies to all gold-negative patients. All patients share the same study period and any detection within it counts as FP.

Return value

  • $confusion — 2×2 matrix: rows = Gold (Positive / Negative), columns = Computed (Detected / Not detected).
  • $metrics — One-row tibble: n_gold_positive, n_gold_negative, TP, FN, FP, TN, sensitivity, specificity, PPV, NPV, accuracy, F1, kappa.
  • $detail_positive — Gold-positive rows with detected (logical) and classification ("TP" / "FN").
  • $detail_negative — Gold-negative rows with detected (logical) and classification ("FP" / "TN").

Example

# Stage 1: detection
det <- evaluate_detection(
  computed_df      = baseline_ep,
  gold_positive_df = gold_positive,
  gold_negative_df = gold_negative,
  detection_threshold = 0
)
det$confusion   # 2×2 table
det$metrics    # kappa, sensitivity, specificity, PPV, NPV, F1

# Stage 2: dose accuracy restricted to true positives
tp_episodes <- det$detail_positive |>
  filter(classification == "TP")
ev <- evaluate_against_gold(baseline_ep, tp_episodes,
                             gold_id_col   = "patient_id",
                             gold_dose_col = "median_daily_dose")
ev$summary    # MAE, MBE, MAPE among confirmed users we detected

Visualization

Two functions produce dose trajectory charts. Both require ggplot2 (and shiny + DT for the interactive dashboard), which are optional dependencies.

Static timeline plot

plot_patient_episodes( episode_list, patient_ids, gold_std = NULL, drug_filter = NULL, dose_col = "median_daily_dose", gold_dose_col = "median_daily_dose", gold_id_col = "patient_id", colors = NULL, linewidth = 2, title = "Patient dose episodes" )

Returns a ggplot object showing horizontal step segments per episode, faceted by patient × drug. Each method gets a distinct colour; the gold standard is drawn as a dark-grey dashed line. 

p <- plot_patient_episodes(
  list(Baseline = baseline_ep, NLP = nlp_ep),
  patient_ids = c(101L, 102L),
  gold_std    = gold_std
)
print(p)
ggplot2::ggsave("dose_review.pdf", p, width = 12, height = 8)

Interactive dashboard v0.1.3 v0.2.5 raw_list

launch_dose_dashboard( episode_list, raw_list = NULL, gold_std = NULL, dose_col = "median_daily_dose", gold_dose_col = "median_daily_dose", gold_id_col = "patient_id", plot_height = 500L )

Opens a Shiny app in the browser. The main panel has three tabs:

  • Timeline — dose trajectory plot overlaying all selected methods and the gold standard in distinct colours.
  • Episodes — episode-level summary table, sortable and downloadable as CSV.
  • Raw Records v0.2.5 — prescription-level diagnostic table showing the original rows with sig, imputation_method, daily_dose_mg_imputed, pred_equiv_mg, etc. Rows are colour-coded by method to match the plot palette. Includes per-column search filters and a CSV download. Only populated when raw_list is supplied.
