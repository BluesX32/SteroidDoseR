Baseline method

The Baseline method estimates daily dose from structured OMOP fields using a four-step cascade. It tries each method in order and uses the first that produces a non-NA result.

StepLabelFormulaRequires
M1originalPre-existing daily_dose or daily_dose_mg if numeric and > 0daily_dose or daily_dose_mg
M2tablets_freqtablets × freq_per_day × strength_mgtablets, freq_per_day, strength_mg — requires SIG parsing first
M3actual_duration(quantity × strength_mg) / (end_date − start_date + 1) — Burkard (2024) standard for oral tablets v0.1.7quantity, date columns, strength_mg
M4supply_based(quantity × strength_mg) / days_supply — fallback only v0.1.7quantity, days_supply > 0, strength_mg

Workflow

OMOP drug_exposure (all drugs, all routes)
          │
          ▼
  standardize_drug_name(drug_concept_name)  →  drug_name_std
          │
          ▼  filter_oral = TRUE
  ┌───────────────────────────────────┐
  │ Gate 1: oral route only                   │
  │  classify_route(route_concept_name,       │
  │                 route_source_value,       │
  │                 drug_source_value)        │
  │  keep: "oral" or NA (unknown)             │
  └───────────────────────────────────┘
          │
          ▼
  ┌───────────────────────────────────┐
  │ Gate 2: known systemic steroids   │
  │  drug_name_std ∈ pred_equiv_table │
  └───────────────────────────────────┘
          │
          ▼
  strength_mg
  ├─ amount_value  (amount_unit_concept_id == 8576, 0, or NA)
  └─ fallback: mg regex on drug_source_value
          │
          ▼
  Imputation cascade  (first non-NA wins)
  ├── M1  original       pre-existing daily_dose / daily_dose_mg
  ├── M2  tablets_freq   tablets × freq_per_day × strength_mg
  ├── M3  actual_dur     (quantity × strength_mg) / (end_date − start_date + 1)  ← Burkard formula
  └── M4  supply_based   (quantity × strength_mg) / days_supply                  ← fallback
          │
          ▼
  Plausibility cap: doses > 2000 mg/day → NA + warning

strength_mg derivation

Unit safety (v0.1.1 / v0.1.6) amount_value is accepted when amount_unit_concept_id is the OMOP mg concept (8576), is absent/unknown (NA), or is the OMOP "No matching concept" sentinel (0). Many production CDMs write 0 instead of NULL for an unmapped unit; this is treated identically to NA. If the unit is mcg (9655), g (8504), or any other explicit non-mg concept, the value is discarded and the function falls back to extracting mg from drug_source_value (e.g. "PREDNISONE 5 MG TABLET"). Before v0.1.6, concept 0 was incorrectly rejected as non-mg, causing all imputation methods to return "missing" at sites that use the 0 sentinel.

Plausibility cap

max_daily_dose_mg (v0.1.1) Records whose imputed dose exceeds max_daily_dose_mg (default 2000) are set to NA with a warning counting affected rows. Pass NULL to disable. Raise the threshold if your cohort includes high-dose pulse therapy (> 2000 mg/day IV methylprednisolone).

Example

baseline_df <- calc_daily_dose_baseline(
  drug_df,
  m2_sig_parse      = "auto",  # parse SIG to enable M2
  max_daily_dose_mg = 2000
)
table(baseline_df$imputation_method, useNA = "ifany")

NLP method

The NLP method parses the free-text sig column using a hierarchy of regex rules. Before parsing, it filters to oral systemic corticosteroids by route and drug name.

Parsing pipeline

Each record's SIG string passes through the following steps in order:

  1. Normalise — lowercase, collapse whitespace; translate English/Spanish number words to digits ("two" → 2, "dos" → 2); strip pure-word parentheticals like (oral) while preserving (10 mg).
  2. Flag detection — free-text ("as directed", "per physician"), taper ("taper", "decrease", "then X mg"), PRN ("as needed").
  3. Tablet count — regex for "N tablets / tabs / pills / caps".
  4. Frequency extraction — 11 priority phases evaluated in order:
    1. every N hours / qNh → 24/N per day
    2. N times a day / "twice daily" → N per day
    3. Latin abbreviations: QID = 4, TID = 3, BID = 2
    4. Once-daily keywords: QD, daily, every day, every morning, every 24 hours
    5. Every other day / QOD / alternate day → 0.5 per day
    6. every N days / qNd → 1/N per day
    7. N times per week / twice weekly → N/7 per day
    8. every N weeks → 1/(N×7) per day
    9. Once weekly / q7d / weekly → 1/7 per day
    10. Monthly / q30d → 1/30 per day
    11. Remaining once-daily synonyms: nightly, every evening, "once oral", "by mouth" with no other frequency cue
    When no tablet count appears in the SIG, tablets defaults to 1. v0.1.9
  5. mg extraction — 5 sources evaluated in priority order:
    1. (X mg total) — explicit daily total in parentheses → used directly
    2. (X mg per dose) — per-administration total → not multiplied by tablet count
    3. (X mg) — plain parenthetical → per-tablet strength × tablet count
    4. X mg/day / X mg per day — explicit daily total → used directly
    5. Bare X mg — per-tablet strength × tablet count
  6. Daily dose = mg_total or mg_per_day (direct), otherwise mg_per_admin × freq_per_day.
  7. v0.1.1 v0.4.0 Strength fallback — records with freq but no mg use amount_value (unit-checked: amount_unit_concept_id must be 8576 mg, 0, or absent; mcg/g values are discarded) then mg parsed from drug_concept_name. Promotes "no_parse" → "ok" for the common OMOP pattern where the SIG says "take 1 tablet daily" but the dose lives in drug_strength.
  8. v0.4.0 Structural fallback — all records where daily_dose_mg is still NA — including "prn", "taper", and "free_text" — fall back to Baseline M1 (original daily dose field), M3 (actual duration), and M4 (quantity/days_supply). This guarantees NLP coverage ≥ Baseline. When baseline succeeds, the record carries parsed_status = "fallback_<method>". When baseline also fails, the original NLP status ("prn", "taper", etc.) is preserved so callers know which category was unresolved.
  9. Plausibility cap — doses > max_daily_dose_mg (default 2000) are set to NA with parsed_status = "implausible" and a warning.
  10. Status assigned: "ok", "prn", "taper", "free_text", "no_parse", "empty", "fallback_original", "fallback_actual_duration", "fallback_supply_based", "implausible".

Advanced NLP method v0.1.2

calc_daily_dose_nlp_advanced() extends the standard NLP method with richer SIG vocabulary and taper schedule decomposition. It returns the same columns as calc_daily_dose_nlp() and is fully compatible with convert_pred_equiv() and build_episodes().

What is new over standard NLP

Shared components The frequency extractor (.extract_freq()), mg hierarchy, flag detection, and structural fallback are identical in both NLP and Advanced NLP. All frequency patterns — including weekly, monthly, every-N-days, and every-N-hours — are available in both methods.

Advanced NLP adds two things the standard parser cannot handle:

  • Half-tablet and fractional counts — "half a tablet", "1/2 tab", "½ cap", compound forms like "2 and a half tablets" (→ 2.5), and "a tablet" as a synonym for 1. The standard parser requires an explicit digit (e.g., "2 tablets"); English number words ("one", "two", …) are pre-processed to digits by both parsers.
  • Taper schedule decomposition — when expand_tapers = TRUE, taper records are expanded into one row per dose step, each with its own daily_dose_mg, taper_step, step_start_day, and step_end_day. Two strategies are attempted: explicit multi-step ("X mg for N weeks, then Y mg…") and decrement pattern ("start 60 mg then decrease by 10 mg every week").

Taper schedule decomposition

Two decomposition strategies are tried in order:

  1. Explicit multi-step — SIG contains ≥ 2 blocks of the form "X mg [freq] for N [unit]" separated by "then", commas, or semicolons
  2. Decrement pattern — SIG states a starting dose and fixed reduction: "start 60 mg then decrease by 10 mg every week" → generates descending steps

Example: explicit multi-step taper

adv_df <- calc_daily_dose_nlp_advanced(drug_df, expand_tapers = TRUE)

# Compute actual step dates from prescription start
adv_df |>
  dplyr::filter(!is.na(taper_step)) |>
  dplyr::mutate(
    step_start_date = drug_exposure_start_date + step_start_day,
    step_end_date   = drug_exposure_start_date + step_end_day
  ) |>
  dplyr::select(person_id, drug_name_std, taper_step,
                step_start_date, step_end_date, daily_dose_mg, parsed_status)

NLP Notes method (medspaCy) v0.5.0

calc_daily_dose_nlp_notes() extends the NLP pipeline to handle narrative clinical note text — free-text provider documentation such as "Patient has been on prednisone 40 mg daily, tapered to 20 mg over the past month." It runs the Advanced NLP SIG parser first (fast path), then routes only unresolved records through a medspaCy Python pipeline for entity-level extraction, negation/uncertainty detection, and section awareness.

Python dependency required medspaCy is an optional dependency. Install it before first use: 
pip install medspacy scispacy
python -m spacy download en_core_sci_sm
The package checks for medspaCy availability with a clear error message and installation instructions if it is not found.

Five-step pipeline

OMOP drug_exposure + clinical note text
          │
          ▼  Step 1
  Advanced NLP SIG parser (parse_sig_advanced)
  → fast path; handles structured SIGs
          │
          ▼  Step 2 (only for rows that failed SIG parsing)
  medspaCy Python pipeline
  → handles narrative / free-text note content
  → negation, uncertainty, historical context detection
  → section awareness (history / assessment / plan)
          │
          ▼  Step 3
  Strength fallback
  → amount_value (unit-checked: concept 8576 / 0 / NA only)
  → mg regex on drug_concept_name / drug_source_value
          │
          ▼  Step 4
  Baseline structural fallback (M1 / M3 / M4)
  → fills remaining NA rows from structured OMOP fields
          │
          ▼  Step 5
  Plausibility cap (max_daily_dose_mg = 2000)

Hierarchical method v0.5.0

calc_daily_dose_hierarchical() cross-checks the Baseline estimate (M1/M3/M4 only — quantity/supply side) against the Advanced NLP SIG estimate (text side) and applies a decision tree to choose the most credible result. Because M2 (tablets×freq from SIG) is deliberately excluded from the Baseline side, the two estimates are truly independent: Baseline uses structured OMOP quantity fields; NLP uses free-text SIG instructions.

Decision tree

Per-row logic
┌────────────────────────────────────────────────────────────────────┐
│ bl_complete = Baseline M1/M3/M4 produced a non-NA dose             │
│ sig_complete = SIG parsed cleanly (parsed_status == "ok")          │
│ is_taper     = SIG flagged as taper/taper_ok                       │
└────────────────────────────────────────────────────────────────────┘

Case 1: bl_complete AND sig_complete
  dose_diff = |bl_dose − sig_dose|   (absolute difference in mg/day)
  ├─ dose_diff ≤ match_tol (1 mg)           → "cross_checked"        use NLP dose
  ├─ dose_diff > diff_threshold (5 mg)      → "nlp_override"         use NLP dose
  └─ match_tol < dose_diff ≤ diff_threshold → "nlp_preferred"        use NLP dose (default)
                                             → "baseline_preferred"   use Baseline dose
                                             → "blended"              use avg(bl, nlp) (legacy)
     ↑ controlled by moderate_disagreement_action parameter

Case 2: bl_complete, sig absent or unparseable
  → "baseline_only"   use Baseline dose

Case 3: bl_incomplete, sig available
  ├─ sig_complete AND NOT is_taper         → "nlp_fills_baseline"
  │     strength from Baseline amount_value; compute dose from SIG tablets/freq
  └─ is_taper                              → "nlp_taper"
         NLP handles the record directly

Case 4: bl_incomplete AND no sig
  → "missing"   daily_dose_mg = NA

Why M2 is excluded from the Baseline side M2 derives dose from SIG text (tablets × freq × strength). Including it would make the Baseline and NLP estimates use the same SIG information, eliminating the independence that makes the cross-check meaningful. The Baseline side uses only M1 (pre-existing dose field), M3 (quantity / actual duration), and M4 (quantity / days_supply) — all derived purely from structured OMOP quantity fields.
